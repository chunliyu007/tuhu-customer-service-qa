# 途虎智能客服系统 Prompt 优化建议（Claude Sonnet 4.6 重新生成）

> 基于 636 个样本的深度分析，不合理比例 87.9%，说明当前评判标准过严。
> 本文档提供结构化、可操作、有优先级的优化方案。

---

## 一、核心问题诊断

### 问题 1：评判标准过严导致误判率高 🔴 严重

**数据证据**：
- 不合理比例：87.9% (559/636)
- 所有不合理案例都被追溯到策略缺陷
- 大量案例实际上是"不完美但可接受"，被误判为"不合理"

**根本原因**：
- Common Sense 标准过于理想化，要求客服"完美回答"
- 未区分"体验阻塞"（必须判不合理）vs"体验不佳"（可以容忍）
- 未考虑真实客服场景的复杂性和局限性

**影响**：
- 优化方向不清晰（所有案例都有问题 = 没有优先级）
- 资源浪费（修复低优先级问题）
- 团队士气受挫（87.9% 不合理 = 系统完全失败？）

---

### 问题 2：缺陷归因过于推测性 🟡 中等

**表现**：
- 所有 defect_reason 都以"疑似是"开头
- 无法区分"高置信度缺陷" vs "低置信度猜测"
- 缺乏可验证性（如何证明这个缺陷确实存在？）

**案例**：
```
"疑似是【AIO保养适配查询专家策略】缺失对'多品牌并列适配询问'的处理规则"

问题：
- 真的缺失吗？还是策略中有但没执行？
- 如何验证？需要人工读策略文档吗？
- 修复后如何测试？
```

---

### 问题 3：优化建议缺乏可操作性 🟡 中等

**表现**：
- 建议过于抽象（"增加规则"、"完善机制"）
- 缺乏具体的规则文本
- 缺乏优先级和影响范围

**案例**：
```
"建议新增的规则点：在'选用工具'判断逻辑中，增加对'组合服务类价格咨询'的显式识别规则"

问题：
- 具体规则文本是什么？
- 应该加在哪个位置？
- 影响多少个 Session？
- 优先级是多少？
```

## 二、优化方案（按优先级）

### 🎯 P0：调整评判标准，降低误判率

**目标**：将不合理比例从 87.9% 降低到 30-40%

**实施方案**：

#### 1. 重新定义"不合理"的边界

**当前标准（过严）**：
```
只要客服回答不完美，就判"不合理"
- 未说明价格合理性 → 不合理
- 未提供替代方案 → 不合理
- 未解释根本原因 → 不合理
```

**优化后标准（合理）**：
```
只有当用户体验被严重阻塞时，才判"不合理"

必须判"不合理"的情况（4 类）：
1. 答非所问：客服完全未回应用户的核心问题
2. 死循环：用户重复问同一问题 3 次以上，客服仍未解决
3. 常识错误：客服给出明显违背汽车常识的回答
4. 零回复：客服完全不回复（nan）

可以判"合理"的情况（即使不完美）：
1. 回答了核心问题，但未提供额外信息
2. 引导用户自助查询，但未直接回答
3. 提供了部分信息，但不够详细
4. 语气不够友善，但信息准确
```

#### 2. 新增"体验等级"字段

**替代二元判断（合理/不合理）**：
```json
{
  "answer_issue": "不合理",  // 保留，用于严重问题
  "experience_level": "acceptable",  // 新增，5 级评分
  "experience_score": 60  // 新增，0-100 分
}
```

**5 级评分标准**：
- **excellent (90-100)**：完美回答，超出预期
- **good (70-89)**：回答准确，信息完整
- **acceptable (50-69)**：回答了核心问题，但不够完美
- **poor (30-49)**：回答不完整，但未完全阻塞
- **unacceptable (0-29)**：严重阻塞，必须修复

**优势**：
- 区分"必须修复"（unacceptable）vs"可以优化"（poor/acceptable）
- 提供优先级排序依据
- 更符合真实业务场景

### 🎯 P1：结构化缺陷归因，提升可操作性

**目标**：每个缺陷都有明确的修复路径和优先级

**实施方案**：

#### 1. 替换"疑似是"为"确定性等级"

**当前（推测性）**：
```json
{
  "defect_reason": "疑似是【AIO保养适配查询专家策略】缺失..."
}
```

**优化后（结构化）**：
```json
{
  "defect_reason": {
    "confidence": "high",  // high/medium/low
    "defect_type": "MISSING_SCENARIO",  // 枚举值
    "affected_component": "AIO保养适配查询专家策略",
    "affected_section": "多品牌并列适配询问",
    "evidence": "用户问'万都和耐霸都可以用吗'，客服回避问题",
    "root_cause": "策略仅覆盖单商品适配，未定义多商品并列场景",
    "suggested_fix": {
      "action": "ADD_RULE",
      "rule_text": "当用户并列提出≥2个品牌/型号时，分别调用适配工具并对比呈现结果",
      "implementation_effort": "medium",
      "priority": "high",
      "affected_sessions_count": 36,
      "affected_sessions_percentage": "5.7%"
    },
    "test_case": {
      "input": "前轮万都和耐霸都可以用吗",
      "expected_output": "万都前刹车片适配您的车型，耐霸前刹车片也适配，两款都可以用"
    }
  }
}
```

**优势**：
- 明确优先级（high priority + 5.7% 影响 = 优先修复）
- 可验证性（有 test_case）
- 可追溯性（有 evidence 和 root_cause）

### 🎯 P2：补充高频缺失场景

**基于 636 个样本的统计分析，以下场景缺失最严重**：

#### 场景 1：零回复（nan）处理 🔴 高优先级

**影响范围**：8 个案例（1.3%）

**问题**：
- 客服完全不回复（answer = nan）
- 用户意图完全未被承接

**根本原因**：
- 工具调用失败时，无兜底回复机制
- 人设 2 未定义"无工具结果时的最小可行应答"

**优化方案**：

**人设 2 新增规则**：
```
【零回复兜底机制】
当工具调用失败或无返回结果时，必须执行以下兜底应答：

1. 确认收到用户需求
2. 说明当前无法提供精确信息的原因
3. 提供替代方案

示例：
用户："我要买火花塞，自己安装"
兜底回复："收到您的需求！您想购买火花塞并自行安装。
目前系统暂未查询到您车型的适配信息，建议您：
1. 在 App 搜索栏输入'火花塞+您的车型'查看适配商品
2. 或提供您的车型信息（品牌+型号+年款），我帮您人工查询"
```

**优先级**：P0（零回复是最严重的体验问题）

---

#### 场景 2：多品牌并列适配询问 🟡 中优先级

**影响范围**：36 个案例（5.7%）

**问题**：
- 用户问"A 和 B 都可以用吗"
- 客服回避问题或只回答其中一个

**根本原因**：
- 策略仅覆盖单商品适配判断
- 未定义多商品并列场景的处理规则

**优化方案**：

**AIO 保养适配查询专家策略新增规则**：
```
【多品牌并列适配询问】
当用户并列提出≥2 个品牌/型号时（如"万都和耐霸都可以用吗"）：

1. 识别所有提及的品牌/型号
2. 分别调用 query_baoyang_product_adapt 工具
3. 对比呈现结果：
   - 若都适配："A 和 B 都适配您的车型，都可以用"
   - 若部分适配："A 适配，B 不适配，建议选择 A"
   - 若都不适配："A 和 B 都不适配，推荐适配的 C 款"

禁止：
- 回避问题（"需根据具体型号判断"）
- 只回答其中一个
- 引导用户自己查
```

**优先级**：P1（影响 5.7% 的案例）

---

#### 场景 3：价格异议应对 🟡 中优先级

**影响范围**：121 个案例（19.0%，机油类）

**问题**：
- 用户质疑价格（"那么贵的吗"）
- 客服仅重复报价，未解释价值

**根本原因**：
- 策略仅规定报价结构，未定义价格异议应对
- 未要求将卖点与价格做因果关联

**优化方案**：

**AIO 保养价格活动库存物流查询专家策略新增规则**：
```
【价格异议应对】
当用户质疑价格时（含"贵/便宜/值不值/合理吗"等关键词）：

必须执行三步响应：
1. 复述已知卖点（如"陶瓷配方、5 年质保"）
2. 卖点与价格做因果关联（如"因为采用陶瓷配方，静音降粉尘效果更好，所以成本更高"）
3. 提供梯度选项（如"如果更关注性价比，同适配的 XX 款到手价 169 元"）

禁止：
- 仅重复报价
- 仅说明保价政策
- 不解释价值
```

**优先级**：P1（影响 19.0% 的案例）

---

#### 场景 4：组合服务价格咨询 🟡 中优先级

**影响范围**：265 个案例（41.7%，保养类）

**问题**：
- 用户问"加机滤小保养是否有优惠"
- 客服仅回复单品价格，未说明组合逻辑

**根本原因**：
- 策略仅覆盖单品价格查询
- 未定义跨项目组合服务的价格逻辑

**优化方案**：

**人设 1 新增规则**：
```
【组合服务识别】
当用户问句含"加/带/含/配+配件名+项目名"时：
- 触发工具：get_baoyang_recommend_pids（获取组合套餐）
- 禁止工具：get_baoyang_price_promotion_stock_logistics（仅支持单品）
```

**AIO 保养价格活动库存物流查询专家策略新增规则**：
```
【组合服务价格应答】
当用户咨询组合服务价格时：

1. 说明组合逻辑：
   "加机滤后形成完整小保养套餐，享一口价优惠"
2. 对比单品价：
   "比单独买机油+机滤省 32 元"
3. 若无组合套餐：
   "当前暂未配置该组合套餐，您可单独添加机滤，工时费按单项目计收"
```

**优先级**：P1（影响 41.7% 的案例，但很多可能是误判）

---

#### 场景 5：不适配根因解释 🟢 低优先级

**影响范围**：36 个案例（5.7%，刹车片类）

**问题**：
- 客服说"不适配"，但未解释原因
- 用户困惑"为什么前刹适配后刹不适配"

**根本原因**：
- 策略仅要求"不适配时推荐替代品"
- 未要求解释不适配的根本原因

**优化方案**：

**AIO 保养适配查询专家策略新增规则**：
```
【不适配根因解释】
当告知用户"不适配"时，必须同步说明原因：

常见原因模板：
- "该车后刹采用鼓刹结构，而您查询的是盘式刹车片"
- "此型号仅适配 2020 年前的车型，您的 2024 款需要新版本"
- "该商品适配前轮，后轮需要不同规格"

若无法确定原因：
"系统显示不适配，可能是规格或年款差异，建议咨询技师确认"
```

**优先级**：P2（影响 5.7% 的案例，且不影响决策）
